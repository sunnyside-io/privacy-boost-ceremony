## What a release carries

Every `ceremony/v*` release publishes sixteen assets: four platform tarballs, each with a `.sha256` and a `.cosign.bundle`, plus `contribute.sh` and `production.ceremony.config.json`, each with its own cosign bundle. A release is therefore self-contained. Verifying a contribution made against it never requires reading `main`.

The config asset is the authoritative copy for a given tag. A release binary is stamped with the SHA256 of the config it was built against and refuses to run against config bytes that do not match, which surfaces any config-to-binary skew before any download or compute begins.

## Bundle digests

The two digests in the table above pin the published public bundle. `manifest.json` hashes to the bundle manifest SHA256. The bundle root SHA256 is the value `manifest.json` itself commits to, computed over every file in the bundle except the manifest.

`verify-public` recomputes the bundle root, every artifact digest, and every contribution digest, so a truncated or altered download fails long before the key re-derivation phase begins. What that check cannot do is separate the real bundle from a fabricated one that is internally consistent, because the root is computed over everything except the manifest that carries it. Comparing the manifest digest against the value recorded here closes that gap, because this page is version controlled and does not come from the download host.

Check it before running verification:

```bash
shasum -a 256 <BUNDLE_DIR>/manifest.json
```

The manifest also commits a digest of `config.snapshot.json`, the coordinator's exported runtime config. That is a different file from the repo config named in the table above, so the two config digests are not expected to match.

## Transport

The coordinator serves plain HTTP. This is a deliberate choice for this round. The consequence is that a contributor session token is observable on the network, so an observer positioned to see the traffic could hijack a live session and submit under that contributor's name. It does not expose secret material, because the ceremony transcript is publicly verifiable either way and a contribution's soundness does not rest on the transport.
