## Verification limits

The `v0.1.x` releases predate the signing and config-publishing work that landed for the second round. Each of them carries only the four platform tarballs and their `.sha256` files. There is no cosign bundle and no published config asset, so a first-round release binary can be checked against its published checksum but its signature cannot be verified after the fact, and the config it ran against is only recoverable from this repository rather than from the release itself.

That gap cannot be closed retroactively. It is the reason the second round publishes the config and a cosign bundle as release assets.
