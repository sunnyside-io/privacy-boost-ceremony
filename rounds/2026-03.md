## What a release carries

Every `ceremony/v*` release publishes sixteen assets: four platform tarballs, each with a `.sha256` and a `.cosign.bundle`, plus `contribute.sh` and `production.ceremony.config.json`, each with its own cosign bundle. A release is therefore self-contained. Verifying a contribution made against it never requires reading `main`.

The config asset is the authoritative copy for a given tag. A release binary is stamped with the SHA256 of the config it was built against and refuses to run against config bytes that do not match, which surfaces any config-to-binary skew before any download or compute begins.

## Transport

The coordinator serves plain HTTP. This is a deliberate choice for this round. The consequence is that a contributor session token is observable on the network, so an observer positioned to see the traffic could hijack a live session and submit under that contributor's name. It does not expose secret material, because the ceremony transcript is publicly verifiable either way and a contribution's soundness does not rest on the transport.
